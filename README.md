# 高等教育ニュース収集・共有アプリ（試作版）

神戸大学、国立大学、高等教育政策・予算、認証評価、法人評価、文部科学省、
入試・就職・大学ランキングなどの公開ニュースを自動収集し、閲覧者自身が
必要な記事を探せるようにする個人運営の情報整理アプリです。収集処理と公表画面を分離し、
公表画面は保存済みの公開用データだけを読み込みます。

## 現在できること

- 13の情報源・ニュース検索を毎日朝8時頃に1回だけ更新
- 収集担当はSQLiteへ履歴を保存し、公表用JSONを生成
- 公表画面は外部サイトへ収集に行かず、公開用JSONだけを読み込む
- SQLiteデータベースへの重複を除いた保存
- 新聞・雑誌・Googleニュース経由の記事は公表画面で概要を非表示
- 公的機関と正式RSSが配信する概要は公表画面で活用
- 公開日時（不明時は初回取得日時）が3日以内の記事に赤い「NEW!」を表示
- NEW記事の主語別件数・タイトル一覧・URLを画面上部に表示し、テキストでも保存
- 4つの主語＋「すべて」の記事数・本日公開記事数・媒体数を一覧表示
- 赤・橙・黄・青・紫の行タイトルをクリックして記事一覧を絞り込み
- 神戸大学関係を起動時に選択
- 媒体、期間、キーワードによる絞り込み
- 「すべて」を初期値とするテーマによる横断的な絞り込み
- 無料・有料・不明の推定分類
- 1つの情報源が失敗しても、ほかの取得を継続
- 取得失敗と件数の記録

担当者による掲載可否の判断や所見の入力は必要ありません。自動分類は記事を
削除するためではなく、探しやすくするために使用します。

## 使用している情報源

### 直接取得

- 神戸大学ニュース・お知らせ・イベント（公式RSS）
- 文部科学省（公式RSS）
- 大学改革支援・学位授与機構（公式RSS）
- 大学ジャーナルオンライン（RSS）
- 大学プレスセンター（公開記事一覧）
- ベネッセ VIEW next（公開記事一覧）

### 一般ニュース検索

- 神戸大学／Kobe University
- 国立大学の予算・政策・改革・評価
- 高等教育の政策・予算
- 認証評価・法人評価・内部質保証
- 大学入試・就職・ランキング

一般ニュース検索では公開RSSを利用しています。検索サービスの仕様変更により、
将来取得できなくなる可能性があります。広告・プレスリリース色の強い記事を減らすため、
PR TIMESは媒体名または記事タイトルで判定し、保存前に除外します。

## データベースに保存する内容

`02_output/higher_education_news.db` はSQLite形式のデータベースです。
記事本文の保管庫ではなく、ニュースを探すための索引として次を保存します。

- 記事タイトル
- 元記事を開くためのURL
- 元サイトが公開している短い概要
- 媒体名と取得方式（RSS、公開記事一覧など）
- 記事の公開日時
- 初めて取得した日時と、最後に確認した日時
- 従来の5分野分類、関連度、神戸大学関係かどうか
- 画面用の主語分類と、記事に0個以上付くテーマ
- 無料、有料の可能性、無料・有料不明の推定
- 一般ニュース検索で使用した検索条件
- 重複を判定するために正規化したタイトル

公式RSSや専門媒体では元記事のURLを保存します。一般ニュース検索では、
検索サービスを経由して元記事を開くURLになる場合があります。

別の表には、記事と複数テーマの対応、情報源ごとの更新開始・終了日時、成功・失敗、
取得件数、新規件数、エラー内容を保存します。また、分類ルールの版番号も保存します。
従来の分類列は削除・上書きせず残しているため、今回の方式から戻すこともできます。

記事本文、有料部分、パスワード、APIキー、個人情報は保存しません。

## 収集データと公表データの分離

収集担当は `higher_education_news.db` に取得履歴、概要、分類、取得結果を保存します。
公表画面はSQLiteへ接続せず、収集後に生成する `public_news.json` だけを読み込みます。

公表用JSONには、無料と推定し、高等教育との関連度がある記事だけを出力します。
神戸大学、文部科学省、公的機関の概要と、各サイトが正式RSSで配信した概要は活用します。
新聞・雑誌・Googleニュース検索経由の記事は、分類には概要を利用しても、公表用JSONでは
概要を空欄にして、タイトル、媒体名、日付、分類、元記事へのリンクを表示します。

## 文部科学省記事の概要

文部科学省のRSSには、記事タイトル・日付・URLはありますが、記事概要が入っていません。
このため、データベースに概要がない記事だけ公式ページを開き、公開された本文冒頭から
最大400文字を補います。連絡先、委員名簿、PDF閲覧案内などは概要に使いません。
適切な説明文が見つからない場合は、内容を推測せず「文部科学省が情報を公開した」
という短い案内文を表示します。一度保存した概要があれば、更新のたびに同じページを
開かないため、表示速度と文部科学省サイトへの負荷を抑えます。

## NEW表示

公開日時が画面を開いた時点から3日以内の記事に、赤い「NEW!」を表示します。
公開日時を取得できない記事は、初めてデータベースに保存した日時を代わりに使います。
ちょうど3日前の記事はNEWに含み、3日を超えると自動的に表示が外れます。

画面上部の「NEWタイトル一覧を開く」には、現在NEW表示の付く記事を4つの主語別に
まとめて表示します。「NEW概要をテキスト保存」では、記事タイトル、元記事URL、
ニュースサイトURLを含む共有用の下書きを保存できます。

## 一日一回のメール配信（次の段階）

自動メールはまだ送信しません。毎日同じ記事を繰り返さないよう、メール版では
「公開3日以内」ではなく「前回の正常送信後に初めて取得した記事」を対象にします。
想定する流れは次のとおりです。

1. Windowsのタスクスケジューラなどで一日一回ニュースを更新
2. 前回送信後の新規記事を主語別にまとめる
3. 件数、タイトル、元記事URL、共有ニュースサイトURLを1通のメールにする
4. 正常送信した日時と件数をデータベースへ記録

実装前に、職場で使える共有ニュースサイトのURLと、承認されたメール送信方法
（Microsoft 365／Outlookなど）を決めます。`http://localhost:8501` は起動した
パソコンだけで使えるURLなので、そのまま同僚向けメールには載せられません。
パスワードや認証情報はソースコードやデータベースへ保存しません。

## 初回準備

PowerShellでこのフォルダを開き、次を実行します。

```powershell
python -m pip install -r requirements.txt
```

現在のパソコンでは必要なライブラリがすでに確認されています。

## ニュースを更新する

閲覧画面から収集処理と手動更新ボタンを取り除いています。閲覧者が画面を開いても、
神戸大学、文部科学省、各媒体、Googleニュースへのアクセスは発生しません。

手元で収集用SQLiteと公表用JSONを更新する場合は、PowerShellで次を実行します。

```powershell
python .\03_scripts\collect_news.py
```

Streamlit Community Cloud向けには `.github/workflows/daily_news.yml` を用意しています。
GitHub Actionsは協定世界時で動くため、`23:00 UTC` を指定し、日本時間の翌朝8時頃に
1日1回収集します。1媒体が失敗しても、取得できた情報源の公表データは生成します。
GitHubへ登録後は、Actions画面の `Run workflow` から手動実行して動作確認もできます。
日次処理では `--allow-partial` を使い、失敗した媒体をログへ残しながら、取得できた
媒体の更新結果を正常に公開します。

## 閲覧画面を起動する

PowerShellのスクリプト実行制限に影響されない、次のコマンドを推奨します。

```powershell
python -m streamlit run .\03_scripts\app.py
```

ブラウザが自動的に開きます。開かない場合は、PowerShellに表示される
`http://localhost:8501` をブラウザで開きます。終了するときはPowerShellで
`Ctrl + C`を押します。

## 主語別サマリー表とテーマ

記事を「誰・どの組織の話か」という主語と、「何についての話か」というテーマの
二軸で整理します。起動時は主語「神戸大学関係」、テーマ「すべて」を表示します。

### 主語別サマリー表

- 神戸大学関係
- 文部科学省関係
- 国立大学関係
- その他の大学・高等教育機関
- すべて：4つの主語をまとめて確認する場合に使用

大学改革支援・学位授与機構の記事は「その他の大学・高等教育機関」に入ります。
国立大学の記事は、国立大学協会の2026年4月1日現在の会員名簿を基礎にした大学名でも
判定します。5つの行を選択しなくても、「記事」「うち、本日公開記事」「媒体数」を
同時に比較できます。行タイトルは赤・橙・黄・青・紫の濃い背景色で区別し、クリックすると
その主語の記事だけを表示します。選択中の行にはチェック印と二重枠を付け、未選択の行は
少し薄く表示します。表の件数は、期間・テーマ・媒体・キーワードなど現在の条件を反映します。

### テーマ

右側の主画面で、主語別サマリー表のすぐ上にあるテーマ欄から次のいずれかを選びます。
主語別サマリー表とテーマを近くに置き、「誰の話か」と「何の話か」を続けて指定できます。
左側は、更新、キーワード、媒体、期間という補助的な条件に限定します。

- すべて：テーマで絞り込まない初期状態
- 政策・制度・予算
- 入試
- 学生支援・就職支援・キャリア教育
- 教育
- 研究
- 国際・留学生
- 評価・質保証
- 社会連携・地域貢献

1記事には複数テーマを付けられます。例えば、国立大学の認証評価記事は
「国立大学関係」の行に入り、「評価・質保証」テーマでも見つかります。
大学改革支援・学位授与機構の認証評価記事は「その他の大学・高等教育機関」の行に入り、
同じ「評価・質保証」テーマで見つかります。テーマが付かない記事も削除せず、
テーマ「すべて」では表示します。大学ランキングは専用テーマを設けず、
当面は「すべて」またはキーワード検索で確認します。

## 初期表示の考え方

初期画面では次の条件を使います。

- 主語「神戸大学関係」
- テーマ「すべて」
- 直近7日
- 高等教育との関連度がある記事だけ
- 無料と推定した記事だけ
- 公開日時の新着順

無料条件、関連度条件、並び順は固定し、画面上のスイッチやラジオボタンは表示しません。
「無料・有料不明」「有料の可能性」「関連度が低い候補」もデータベースには保存しますが、
通常画面には表示しません。右側のテーマと、左側の期間・媒体・キーワードは
引き続き変更できます。

## 有料記事判定の限界

有料記事の判定は、媒体名と「会員限定」などの表示に基づく推定です。
一覧では無料でも、記事の途中から有料になる場合があるため、完全な判定はできません。
判定結果は `無料と推定`、`有料の可能性`、`無料・有料不明` の3種類です。

有料部分を回避して取得する処理は実装していません。

## 著作権・情報セキュリティ

- 記事本文をデータベースへ保存しない
- 公開されたタイトル、短い概要、URL、媒体名、日付だけを収集用データへ保存する
- 公表用データでは新聞・雑誌・Googleニュース経由の記事概要を非表示にする
- 公的機関と正式RSSの公開概要は出典・元記事リンクとともに活用する
- 有料部分やログイン後の内容を取得しない
- 参考メールは読み取り対象とし、元ファイルを変更しない
- 外部AIへ記事本文を送信しない
- APIキーや認証情報をソースコードへ書かない

画面下部には次の注意書きを小さく表示します。

> 本サイトは、公開情報を自動収集・分類した個人運営の情報整理サイトです。詳細・正確な内容はリンク先をご確認ください。分類は自動処理による推定です。

収集用SQLiteはGitHubへ登録せず、公表用JSONだけをStreamlit Community Cloudで使用します。
APIキーや認証情報が必要になった場合は、GitHubやコードへ書かずSecretsへ保存します。
